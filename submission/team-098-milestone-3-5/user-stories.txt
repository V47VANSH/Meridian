Team 98 | IITM BS Degree, Software Engineering | May 2026
User Stories


FORMAT AND METHOD
=================

Each story follows the required form:

    As a [type of user], I want [an action], so that [a benefit/value].

Stories were written against the SMART guidelines - each names a specific
actor and action, has an observable outcome that can be demonstrated, is
achievable within a sprint, is relevant to a pain point identified in user
research, and is bounded by the sprint it was scheduled in.

The endpoints listed under each story are not documentation written after
the fact. They are published inside the API contract itself, as an
'x-user-story-mapping' extension in api-doc.yaml, so the traceability from
story to implementation travels with the specification and is regenerated
from the live route table whenever the API changes.

Total: 24 user stories across 6 epics.

E1 — MAINTENANCE MANAGEMENT
==========================================================================

US-1.1
------
  As a resident,
  I want to see my maintenance dues,
  so that I know what I owe and by when.

  Implemented by:
    - GET /api/v1/maintenance/invoices
    - GET /api/v1/maintenance/invoices/{invoice_id}
    - GET /api/v1/maintenance/payments/{payment_id}

US-1.2
------
  As a resident,
  I want to pay my maintenance online,
  so that I do not have to visit the society office.

  Implemented by:
    - POST /api/v1/maintenance/invoices/{invoice_id}/pay
    - POST /api/v1/maintenance/invoices/{invoice_id}/payments/confirm
    - POST /api/v1/maintenance/invoices/{invoice_id}/remind
    - GET /api/v1/maintenance/payments

US-1.3
------
  As a society official,
  I want to raise monthly invoices and track collection,
  so that dues are transparent and auditable.

  Implemented by:
    - POST /api/v1/maintenance/invoices
    - POST /api/v1/maintenance/invoices/{invoice_id}/offline-payment
    - GET /api/v1/maintenance/summary

US-1.4
------
  As a society official,
  I want to know which flats are likely to pay late,
  so that I can send reminders before the due date.

  Implemented by:
    - GET /api/v1/maintenance/flats/{flat_id}/risk-score
